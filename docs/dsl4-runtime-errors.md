# 紙芝居のエラー表示と発生位置

関連Issue: [#1094](https://github.com/kubohiroya/turbowarp-kamishibai-app/issues/1094)

エラー画面は追加設定なしで標準表示する。旧表示との切替フラグは設けない。
画面は、失敗の説明、確認する場所、対処方法、利用可能な操作の順に案内する。
エラーコード・元のメッセージ・実行段階・原因例外等は「技術的な詳細」にまとめる。
原因が不明な場合には、その旨を明示する。

## 検証から表示まで

1. YAMLを解析し、ブロック台本の場合は元ブロックと生成データの対応を記録する。
2. AjvによるJSON Schema検証で型・必須項目・未知の項目・許容値等を検査する。
3. 検証違反をファイル・範囲・パス付きの診断に変換する。任意の`validation`に
   `keyword`、`field`、`expected`を保持する。各文字列の上限は160文字とする。
   `oneOf`／`anyOf`の候補に属する違反は`alternative`で区別し、候補の一つだけが要求する
   型や項目を必須の修正方法として断定しない。
4. 意味検証、参照の解決、式や資源上限の検証はSchemaとは別に行う。
5. 実行時の失敗には、通常の診断とは別に`failureContext`を付ける。
   場面・処理・関係する素材・上限付きの原因例外を画面へ渡す。
6. 共通画面はコードと構造化された情報から日本語／英語の説明と対処を組み立てる。
   未知のエラーの英語メッセージだけから、通信障害や台本の誤りと断定しない。

Schema検証はカメラの利用許可や実行中の素材読込成功を保証しない。
これらの失敗は実行時の例外・コード・処理の種類から案内する。

## ブロックの位置対応

行番号だけでブロックを特定しない。`includeBlocks`の展開・設定の合成前後では
同じ行番号が異なる記述を指すため、必ず元のsourceIdとそのソース内の範囲を組にする。

- コンパイル診断は元ソースのパスから、最も深いブロック位置へ解決する。
- 定義ブロックは値が文字列や数値の場合も、パスとブロックIDを記録する。
- `kamishibaiConfig`を別スプライトから合成する際の一時IDを、元の
  ステージ／スプライト名とブロックIDへ戻す。
- 実行時の診断は、コンパイル時に保持した元ソース内の範囲を位置表と照合する。
  生成台本の行番号は生成物の位置として表示し、元ブロックの編集を案内する。
- 具体的な場所を解決できない診断を、先頭の台本ハットへ無条件に割り当てない。
- 編集・削除・作品切替や診断の差替えで古くなった位置には移動しない。

調査では、`includeBlocks`と別スプライトの設定を併用した際、素材のSchema違反が
設定の定義ブロックではなくStageの台本ハットへ割り当てられる問題を再現した。
定義位置の記録不足と、一時IDから元スプライトのIDへの逆変換不足を修正した。
同一IDが複数のスプライトにある場合と、取り込んだ場面の実行エラーも対象検証する。

## 操作と診断情報

- ホストが対応するときに元ブロック／元ソース行へ移動する。
- 「メニューに戻る」は不正な台本を自動的に再コンパイルしない。
- 戻り先のない環境では「閉じる」を表示する。閉じても再生は再開しない。
- コピー失敗時は選択可能な診断テキストを表示する。診断は画面内にも保持する。
- 非同期の移動・戻る・コピーが終わっても、後から表示された診断を変更しない。
- コピー対象は必要な項目に限定し、ファイル全文・作品全体・FileSystemHandleを
  シリアライズしない。URLの資格情報・クエリ・端末のパス等を除去する。
- 小さいステージでは本文をスクロールさせ、操作ボタンを表示領域内に保つ。

## 検証とロールバック

検証は、表示・診断生成・元ブロックへの位置対応・ホスト統合の対象テストと、
必要な型検査・生成ランタイムの整合性・実Chromeの表示／操作に限定する。

問題時は変更したソースと生成ランタイムを同じ単位でrevertする。
台本や保存データの移行は不要。公開済み同版の成果物は差し替えず、配布の切戻しは
検証済み直前版への導線変更として扱う。
