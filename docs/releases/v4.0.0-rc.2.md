## 概要

v4.0.0-rc.2は、非埋め込みStandard SB3とTurboWarp Editorだけで、台本のpreview、自動検証、
live reload、配布用SB3生成まで行える作者flowを追加する公開候補です。一般作者はNode.js、pnpm、
ターミナルを準備せず、作品フォルダーを選んで編集し、作者用メニューから自己完結SB3を保存できます。

安定版としての推奨は3.2.3を維持し、4.0.0-rc.2は4.0正式公開前のbrowser authoringと配布経路の
検証に使用します。

## rc.1からの主な変更

- 非埋め込みStandard SB3の作者用メニューへ「配布用SB3を作る」を追加
- 最新のsource／asset generationを再読込・再検証してから、browser内で配布用SB3を生成
- current TurboWarp projectのStage、sprite、costume、soundを保持したまま、
  `application.mode=story`の自己完結projectを構築
- local assetをSB3へ埋め込み、remote deliveryとoffline拒否条件を維持
- native save pickerとbrowser download fallback、cancel／failure時の非破壊transactionを追加
- invalid、missing、unstable、pending、permission失効、generation変化をfail closed
- production story SB3ではbrowser build UIを初期化しない
- 非同期カーソル通知の表示／解除順序を保証し、observer failureを入力・発話処理から隔離
- 通常状態でTurboWarp canvasの明示的なpointerを保持し、wait／progress／pointerだけを優先
- 実Chromiumでdirectory open → build → save → fresh VM loadとcomputed cursor styleを検証

## 作者向けflow

1. 非埋め込みStandard SB3をTurboWarp Editorで開き、緑の旗を押します。
2. 作者用メニューの「ファイルを開く」から作品フォルダーを選びます。
3. 外部editorでYAMLやlocal assetを編集します。正常な保存は自動検証後に反映されます。
4. 不正な候補ではlast-known-goodの実行を維持し、診断を表示します。修正後は自動復旧します。
5. メニューへ戻り、「配布用SB3を作る」を押します。
6. 保存したSB3を新しいTurboWarp Editor sessionで開き、作品フォルダーなしに実行します。

CLIの`preview-dsl4`、`validate-dsl4`、`build-dsl4`は、CI、batch build、高度な配布profile、
File System Access API非対応環境向けに維持します。

## 互換性と制約

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- package、Standard Runtime reporter、artifact metadataは`4.0.0-rc.2`に揃います。
- browser authoringはFile System Access APIとsecure contextを利用できるChromium系browserを対象とします。
- 選択したfilesystem handle、absolute path、preview token、diagnostic、reload preferenceはSB3へ保存しません。
- remote assetを選択した配布profileはnetwork依存を維持します。offline profileではremote descriptorを拒否します。
- 3.1／3.2作品はversion 3.2.3の配布SB3で継続利用できます。
- 4.0 Standardは3.2の`extensionBundles`をunbundleして生成するartifactではありません。

## 公開手順

1. clean mainでfull verificationとnpm publish dry-runを実行します。
2. `pnpm release:dsl4:freeze`でsource identityとartifact SHA-256を固定し、freeze PRをmergeします。
3. frozen merge commitへannotated tag `v4.0.0-rc.2`を作成してpushします。
4. `npm publish --access public --tag next`で`@kubohiroya/tmpose-kamishibai@4.0.0-rc.2`を公開します。
5. 本文書をrelease notesとしてGitHub prerelease `tmpose-kamishibai v4.0.0-rc.2`を公開します。
6. `pnpm deploy`で4.0.0-rc.2を公開候補として追加し、3.2.3を推奨安定版のまま維持します。
7. npm、GitHub、PagesのURLを`pnpm release:dsl4:record-publication -- ...`でmetadataへ記録します。
8. npm version／dist-tag、GitHub tag／release、Pages上のSB3 version／SHA-256を再確認します。

## ロールバック

freeze前に問題が見つかった場合はcandidateを修正し、再検証します。freeze後または公開後は
4.0.0-rc.2を同じversionで差し替えません。問題時はnpmの`next` dist-tagをrc.1または次版へ移し、
GitHub prereleaseとPagesへ注意事項を追加します。修正版は`4.0.0-rc.3`として公開します。

公開済み4.0.0-rc.1、安定版3.2.3、version付き3.1／3.2 sourceとartifactは変更・削除しません。
