## 対象と変更

フォーム編集タブで物語を再生した後、停止して再起動するとタイトル待機が解消しない問題を修正しました（[#899](https://github.com/kubohiroya/turbowarp-kamishibai-app/pull/899)、Issue #898）。
カメラの開始応答が保留中でも停止・破棄を進め、緑の旗から再び起動できます。
停止後に到着した古いカメラ取得結果は解放し、次の物語に必要なカメラを維持します。

Stage上の名前が空の台本をルートとして読み、タイトルを閉じると物語を開始します。
ブロックやフォームの編集後は入力を確定し、停止してから緑の旗で起動し、タイトルを閉じてください。
再開始時に現在のブロックを読み直し、編集内容を反映します。
素材同梱、名前付き台本のincludeBlocks、不正台本の診断はrc.23の動作を維持します。

`recognize actor`のポーズ手順（`STEPS`）アイコンからフォームを開けるようにしました（[#905](https://github.com/kubohiroya/turbowarp-kamishibai-app/pull/905)、Issue #904）。
canonical Schemaを使い、各行のpose（必須）、skin・sound（任意）を編集できます。既存8種類の定義フォームにこの1種類を加え、生成SB3へ登録します。既存のブロック台本SB3はrc.25のCLIで再生成してください。

定義・命令をオン／オフにする「この部分を使う」ブロックを追加しました（[#903](https://github.com/kubohiroya/turbowarp-kamishibai-app/pull/903)）。編集用の`sourceSections`設定は既定OFFで、CLIの`--block-sections true`で有効にします。再生時はOFFの範囲を読み飛ばし、再開始時に変更を反映します。StandardのgetInfoは引き続き200ブロック・8メンバーです。

rc.24は公開前の凍結後にmainのruntimeが更新されたため公開を見送りました。同版の成果物を作り直さず、本版を新規凍結しています。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- CLI・開発環境はNode.js 24.0.0以上です。
- Schema、ブロック形式、依存拡張の版はrc.23から変更しません。
- 既存SB3の埋込runtimeは自動更新されません。修正を適用するにはrc.25のruntimeでSB3を再生成してください。
- rc.23以前の固定release artifactを差し替えません。下流は公開済みrc.25のcommit・サイズ・SHA-256へ再pinします。

## ロールバック

問題時はrc.23の公開済みnpm version・依存lock・base artifactのpinへ切り戻し、必要に応じてnpm next/latestをrc.23へ戻します。
samples/docsの今回の更新をrevertし、以前の固定成果物・参照を再配信します。
公開済みrc.25を同じversionで差し替えません。修正が必要な場合は次の候補版を切ります。
