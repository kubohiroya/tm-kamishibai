# 4.0.0-rc.78 — 共通カメラ入口の再接続

対象: [App #1104](https://github.com/kubohiroya/turbowarp-kamishibai-app/issues/1104)。関連する設計: [App #952](https://github.com/kubohiroya/turbowarp-kamishibai-app/issues/952)。DSLは`4.0`、Camera Sourceは公開済み`0.22.1`を維持する。rc.75、rc.76、rc.77の凍結済みmetadata・公開成果物・tagは変更しない。

## 変更

自己完結バンドルではAppがCamera Sourceより先に初期化されるため、タイトルに従来の許可UIが残っていた。依存の同期初期化が完了してからCamera Sourceの公開`registerCameraControls`へ再接続し、停止ボタン後方の共通「カメラ」入口を使う。

Editorは作品読込時にカメラ操作の登録を消去する。Appも古い登録ハンドルを破棄し、読込イベントの処理後に新しいハンドルを登録する。タイトルを閉じた後の遅い再試行は無効化し、カメラ不要作品には入口を追加しない。

登録がない、nullを返す、または失敗するホストでは従来の経路を保つ。登録・開始の成功前に従来UIを削除しない。カメラ許可・設定・取得・共有lease・streamの所有権はCamera Sourceへ委譲し、自動の許可操作や代理クリックは追加しない。

rc.77のブロックアイコンプレビュー・アクター配置編集と、固定Asset Cache 0.6.0への隔離patchを保持する。プレビューは引き続き起動時固定・既定OFFで、対応Editorの`twPlusBlockPreview=1`で有効化する。

## 検証と公開状態

初期化順、作品読込後の再登録、タイトルを閉じた後の取消、重複防止、停止後の再表示、null/例外/未対応ホスト、カメラ不要作品、共有カメラのleaseと所有権を対象テストで検証する。実ローカルEditorでは共通入口1個・旧タイトル許可UIなしと、ブラウザーが描く日本語の許可ボタンを確認している。実機カメラの許可・取得・認識精度は測定していない。

公開前の候補を公式driverで生成・凍結し、CIでsource identityとSB3 bytesを照合する。候補の存在はRelease・npm・Pages公開完了を意味しない。各配信先の実公開記録で状態を確認する。

## 切戻し

元作品を保持し、問題がある場合は元の公開rc.77 SB3へ戻す。修正を戻す場合も既存版を上書きせず、別rcの候補を作る。プレビュー機能だけを無効化する場合はURLの`twPlusBlockPreview=1`と起動前global指定を外して再読み込みする。
