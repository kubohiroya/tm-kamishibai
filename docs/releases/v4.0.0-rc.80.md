# 4.0.0-rc.80 — 台本データの4種類の参照元を共通契約へ接続

関連: [App #1107](https://github.com/kubohiroya/turbowarp-kamishibai-app/issues/1107)、[App #1108](https://github.com/kubohiroya/turbowarp-kamishibai-app/pull/1108)。DSLは`4.0`、Camera Sourceは`0.22.1`を維持する。公開済みrc.79以前のmetadata・tag・配布物は変更しない。

## 変更範囲

DSL 4.0の所有者側を共通のデータソース契約`@kubohiroya/turbowarp-document-source`へ接続する。同じ文書referenceをSB3内ファイル・HTTPS URL・汎用YAMLブロック・台本ブロックの4種類で扱い、所在（location）と表現（representation）を分離する。共通パッケージとEditor側UIは実装済みで、未接続だったのは本リポジトリの所有者providerだけだった。

旧`@kubohiroya/turbowarp-embedded-yaml@0.1.0-rc.2`を`@kubohiroya/turbowarp-document-source`へ置き換える。共通パッケージはnpm未公開のため、commit `a6669566d50062abb39acbb475811cb982e4d85c`のgit pinで参照する。互換facadeによりサブパスのAPIは同一で、`runtime-provenance.ts`と`LICENSES.md`の表記も追従する。

所有者側の新規実装は、起動時固定フラグ`twPlusDocumentSource`（既定OFF、起動環境のみが有効化でき作品データでは有効化できない）、bundled/unbundledに応じた所有者storage IDの選択、表示名「台本データ」/「Script data」、および検証した本文と1バイトでも異なるtextの保存を拒否する候補ビルダーからなる。再生開始時にはURLを再取得して再検証し、機能OFF・通信能力なし・取得失敗・不正DSLのいずれでも保存済みcacheを暗黙に再生せず拒否する。

URL参照の文書は、SB3内へ取り込むまで読み取り専用とし、編集もブロック化もできない。遠隔サイトへ書き戻さない。取得はHTTPSのみ、credentials omit、redirect拒否、UTF-8、既定1MiB/15秒上限とする（共通パッケージ側の実装）。Editor操作用の通信はホストのfetch、再生時は拡張の`Scratch.fetch`を注入して分離する。文書操作区間ではSB3全体のsave/load/stopを一度も呼ばない。

[rc.79](v4.0.0-rc.79.md)のタイトルカメラ判定、[rc.78](v4.0.0-rc.78.md)の依存初期化と作品読込後の再接続、[rc.77](v4.0.0-rc.77.md)の既定OFFプレビューとAsset Cache隔離patchを維持する。

## 検証・公開・切戻し

4種類の参照元、URLの読み取り専用制約、再生時の再取得と拒否経路、保存の同一性検査、文書操作区間でのsave/load/stop呼び出し回数0を対象テストで確認する。`document-source-runtime.js`を依存境界検査の純粋モジュール一覧へ加え、通信能力が注入のみであることを検査で保証する。ブラウザ実機でのEditor↔App通し確認（`?twPlusYamlEditor=1&twPlusDocumentSource=1`）は本候補の凍結後に行う。

公式driverによるrc.80の生成・凍結と公開後のhash照合を分け、候補の存在だけで公開完了を主張しない。npm公開前に、git pinで参照している共通パッケージの扱いを決める必要がある。

切戻しは`twPlusDocumentSource`を外して再起動するだけで、フラグなしの挙動はrc.79と同一である。配布物を戻す場合は公開済みのrc.79 SB3へ戻す。既存版を上書きせず、修正が必要なら次のrcを作成する。
