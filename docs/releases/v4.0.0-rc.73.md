# 4.0.0-rc.73 — 名前付きYAML文書、独立した開始点、3形式の編集と旧SB3移行

DSLの版は引き続き`4.0`です。関連: [Issue #1098](https://github.com/kubohiroya/turbowarp-kamishibai-app/issues/1098)、[Docs #299](https://github.com/kubohiroya/turbowarp-kamishibai-docs/issues/299)。3.2系列の安定版・作品と、公開済みの版付き成果物は保持します。

## 文書と開始点

- `embedded YAML root [4.0] [ファイル名]`を、上下に接続しない独立した開始点として置きます。最初に読む文書を明示し、通常文書の空欄名を開始点とする規則を廃止します。
- 本文は、空欄でないファイル名を持つ通常の`embedded YAML`文書へ接続します。文書の参照IDとファイル名を区別し、同じベース名でも異なる相対パスの文書を混同しません。
- 設定とシーンを同じ通常文書へまとめ、新しい文書パレットと正式移行の最終成果物では`kamishibaiConfig`を生成しません。includeは同じ作品の文書参照として扱い、編集していない相対パスの綴りと各原文ファイルを保持します。旧ハットの読み取り互換は維持します。既存の`author-block-dsl`と低水準の旧形式APIは互換用の生成経路として保持し、その中間成果物には必要に応じて正式移行コマンドを適用します。
- 各文書の原文を保存し、複数文書のブロック表現を同時に保持できます。選択文書だけを保存し、他文書の未反映ブロックや原文を上書きしません。文書自身の競合と、include循環・欠落・台本全体の意味不整合は拒否します。

## TurboWarp-Plus-Editorとの連携

文書操作は既定OFFです。対応するTurboWarp-Plus-Editorを起動するURLに`twPlusYamlEditor=1`を付けると、App側も同じ起動時の指定を読みます。既存の`globalThis.TW_EMBEDDED_DOCUMENT_VIEWS === true`による明示有効化は維持します。作品内の変数や起動後の変更では切り替えません。

文書の書類アイコンから、原文YAML・共通YAMLブロック・台本ブロックを実際のプレビューで確認します。タブの切替だけでは作品を変更せず、「💽=現在保存されている形式」で現在の形式を示します。プレビューは非同期に準備し、古いタブの結果は表示へ戻しません。表示時に作成した変換候補を、同じ文書・同じ状態の保存で再利用します。

「表示されている形式に変換して検証・保存」で、表示した形式を検証してEditor内へ反映します。別形式への反映は確認画面で「OK」を押した後に行います。X・キャンセルは未保存の操作を破棄します。独立した検証・変換候補適用・SB3ダウンロードのボタンは置きません。

現在の共通YAMLブロック・台本ブロックのまま保存する場合も、値や行コメントの変更を原文と再生用データへ反映し、そのブロック形式を維持します。表示時の検証済み候補を再利用し、古い文書状態の候補は保存しません。未編集で原文と等価なブロック文書は、そのまま再生・配布できます。

反映は必要なブロックと文書データの差分を更新します。作品全体のSB3圧縮・解凍・再読み込みや、保存のための一括停止を行いません。無関係なブロックとアセットを保持します。作品ファイルの書き出しにはEditorの通常のファイルメニューを使います。

Editorが読み込み時にビットマップ素材の解像度情報を補正した場合も、同じ名前の素材参照を保って再生・保存できます。文書の保存は素材画像を作り直さず、必要な参照情報だけを合わせます。元の素材バンドルと保持ファイルの整合検査は省略せず、明示的な素材定義や外部ファイルの不整合は引き続き拒否します。

VSCode編集は、専用のローカル補助プロセスを使う明示操作です。文書提供元のJSON Schemaを専用の作業領域へ渡し、保存済みの作業コピーを検証してから取り込みます。既存のVSCode設定は変更せず、取消しや検証失敗でも作業ファイルは保持します。GitHub Pagesから任意のローカルコマンドを起動する機能ではありません。

## コメントと変換の範囲

共通YAMLブロックは、キー・一覧・型付きの値・独立行コメント・行末コメントに対応します。複数行の文字列は、行と改行を明示するブロックで保持します。変更していない原文は、コメント・改行・BOMを含めて保持します。

台本ブロックでは、シーン・命令などへ一意に対応できる独立行コメントを、その位置の行コメントブロックとして扱います。JSON入力内部など、安全に対応付けられないコメントや構造は明示的に拒否します。標準Scratchの付箋をYAMLの行コメントへ勝手に変換しません。未対応構文を削除したり、元の原文が存在しなかった旧SB3へ原文を偽って復元したりしません。

ブロック表現から原文へ反映する際も台本全体を検証します。未変更で原文と等価な表現を保持する作品と、原文へ未反映の編集がある作品を区別します。未反映の編集がある文書を実行・配布用へ使う場合は、その文書を表示した形式のまま検証・保存して、原文と再生用データへ反映してください。

## 編集用Schema

文書提供元は`schema/dsl-4-editor.schema.json`を編集支援へ渡します。通常DSLのSchemaとnarrative文法から生成し、`node scripts/schema/generate-dsl4-editor-schema.mjs --check`で同期を確認できます。通常actionに加え、`if`、`repeat`、`forEach`と有効なscope内のtyped referenceを記述します。未知の通常actionを広いfallbackで受理することはありません。

Schemaによる補完・構造診断は、実行可能性の保証ではありません。展開後の型、scope、scene/asset参照、作品内media、YAMLの安全性、展開量はAppの正本frontendが保存前に検証します。実行用Schemaは維持し、公開済みrc.71の成果物も変更しません。

## 旧SB3の移行

```sh
npx --no-install turbowarp-kamishibai migrate-embedded-yaml \
  --input old-story.sb3 \
  --output named-story.sb3 \
  --entry-file story.k4.yml \
  --report migration-report.json
```

同じ版のCLIを固定して使います。元のSB3は変更せず、既存の出力ファイルも上書きしません。旧主台本と設定を統合し、独立した開始点・名前付き文書・include参照へ移行します。台本全体の意味、アセットのバイト列、無関係なブロックと既存の付箋を検査して保持します。曖昧なラベルや衝突があれば出力を拒否します。

ブロックだけの作品から生成したYAMLは、元のコメントや引用符を復元したものではありません。生成した原文と、保持できない情報を移行レポートで区別します。元作品を残し、新しい作品の各文書と素材を確認してください。

## 検証と公開状態

rc.72は未公開の凍結候補として退避しました。原文と等価な未編集の台本ブロックまで実行を拒否する問題を実Editorで確認したため、同じ版の凍結バイナリを書き換えず、rc.73で修正します。

rc.73では、未変更で原文と等価なブロック表現の実行を許可し、未反映の編集・古い原文・欠落した文書を引き続き拒否します。対象テストに加え、実Editorで浦島とチュートリアルの緑旗再生、同じブロック形式での編集保存、通常のSB3保存・再読込を確認しました。浦島の保存では、素材と無関係なブロックを保持し、作品全体の停止・保存・再読み込みを行わず文書を反映しました。配布SB3とsource identityの正本は、同じ版のrelease metadataです。

App・Samples・Docsと対応するEditorの公開後、同じ版の配布物・Schema・操作導線を照合します。既存SB3に埋め込まれた拡張が自動で更新されることはありません。

## ロールバック

文書操作を有効にする起動指定を外して既定OFFへ戻します。作品は退避した元SB3と対応する旧CLI／ランタイムへ戻し、必要ならrc.71の版付き成果物を使用します。公開済みの同じ版は差し替えず、コードの修正は新しい版として行います。
