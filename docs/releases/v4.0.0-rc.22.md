## 対象

- リモートアセットを取得できないとき、証明書エラーなど原因を示す（#873）
- ローカルプレビューで、実行に失敗したとき黙って止まらずにエラーを表示する（#874）
- 拡張機能をサンドボックス内で許可されたとき、理由と開き直す手順を表示する（#875）

## 概要

3.2では、ポーズモデルのJSONを配信するHTTPSサーバの証明書が期限切れになると、`console.error`が出るだけで
動作が黙って止まりました。rc.21でも失敗はエラーダイアログに出ていましたが、本文はブラウザの
`Failed to fetch`だけで、原因が分かりませんでした。

rc.22のブラウザ側ローダーは、`fetch`が失敗したら同じURLへ`no-cors`でもう一度リクエストし、原因を分けます。

| 状況                       | コード                        | 表示                                                                                           |
| -------------------------- | ----------------------------- | ---------------------------------------------------------------------------------------------- |
| 端末がオフライン           | `K4-ASSET-REMOTE-OFFLINE-001` | ネットワーク接続の確認を促す                                                                   |
| 再リクエストはサーバに届く | `K4-ASSET-REMOTE-CORS-001`    | サーバのCORS設定の問題                                                                         |
| 再リクエストも失敗         | `K4-ASSET-REMOTE-CONNECT-001` | SSL/TLS証明書が期限切れ・無効の可能性が高いこと。URLを直接開いて証明書の警告を確認するよう案内 |

メッセージは日本語・英語をブラウザの言語で選び、URLを含めます。ブラウザのJavaScriptからは、証明書エラーと
DNS失敗・サーバ停止を区別できません。そのため文面は「可能性が高い」にとどめ、他の原因も併記します。

CLI（`lock-dsl4-assets`／`vendor-dsl4-assets`／`convert-dsl4-assets`）では、Nodeのfetchが返すTLSエラーコードから
判定し、`K4-ASSET-REMOTE-TLS-001`で「TLS certificate is not valid (CERT_HAS_EXPIRED): <URL>」のように
確定的に報告します。

ローカルプレビュー（`preview-dsl4`）は、実行の失敗（`runtime.fail`）を受け取っても何も表示せず止まっていました。
rc.22ではStandard SB3と同じエラーダイアログを出し、「メニューに戻る」で戻れます。ローカルプレビューは
リモートアセットを読み込まないため、それが原因の`K4-ASSET-REMOTE-DISABLED`には、ビルドして試すか
プレビュー中はローカル配信に切り替えるよう案内を添えます。**ローカルプレビューがリモートアセットを読み込まない
点は変わりません。**

拡張機能セキュリティで「サンドボックスなしで実行する」にチェックを付けずに許可すると、Runtime memberが例外を
投げてbundleが登録されず、プロジェクトの読み込みが終わらないまま止まっていました。Runtime memberは
`// Unsandboxed: required`を宣言し、sb3-toolchain 0.15.0がこれをbundle全体の要件として記録します。サンドボックス内では
memberを実行せず、同じIDでプレースホルダーを登録し、パレットとコンソールに開き直す手順を出します。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- Extension IDもbundleのmemberも変わりません。rc.21のStandard SB3で作った作品はそのまま開けます。
- block surfaceとcomposition APIは変わりません。台本に書くことは何も増えません。
- リモートアセットの取得失敗は、これまでの`K4-ASSET-REMOTE-LOAD-001`（ブラウザ）／`K4-ASSET-REMOTE-REQUEST-001`（CLI）の
  代わりに、上の新しいコードで報告されることがあります。エラーコードで分岐している下流は確認してください。

### 下流への影響

Standard SB3のバイト列が変わるため、公開済みartifactをベースとして固定している下流は再pinが必要です。

## 検証

```sh
pnpm verify:full
pnpm pack:smoke
pnpm release:check
```

証明書エラーの分類は、ビルドしたローダーのコードを実際のChromeで次のサイトに当てて確認しています。

- expired.badssl.com、self-signed.badssl.com：`CONNECT-001`
- CORS非対応のサイト：`CORS-001`
- 正常なCDN：読み込みに成功

CLI側は、Nodeのfetchで期限切れ・自己署名・ホスト名不一致の各サイトに当て、TLSエラーコードが期待どおり返ることを
確認しています。
