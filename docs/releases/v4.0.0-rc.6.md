## 概要

v4.0.0-rc.6は、camera canvasのcontext選択をTMPoseへ移し、
下流のKamishibaiがTensorFlow.jsの`fromPixels()`経路や警告を補修しない責務境界へ戻す公開候補です。
rendererも公式scratch-renderを直接固定し、Chromiumの回数ベースの警告だけを理由にPackager成果物を
書き換えない責務境界へ戻します。TMPose 1.11.0で公開されたSVGポーズオーバーレイAPIをDSL 4.0へ接続し、
関節とボーンの表示style、最低confidence、confidence連動を台本から宣言できます。

安定版としての推奨は3.2.3を維持し、4.0.0-rc.6は4.0正式公開前の検証に使用します。

## rc.5からの主な変更

- TMPoseを1.11.0へ更新し、1.10.3で移管した通常の2D context選択を維持
- `poseRecognition.preview.overlay`を追加し、TMPoseの公開Composition APIだけで関節とボーンを表示
- overlay専用feature flagを設けず、全DSL 4.0 runtime profileで同じ接続契約を使用
- overlayを省略した既存台本は非表示を維持し、設定時は色、透明度、半径、幅、最低confidence、confidence連動を正規化
- camera canvasの所有者であるTMPoseへ修正を集約し、Kamishibai側の上流内部実装patchを禁止
- scratch-renderを公式commit `a67f7c9c07d459582c227d4fd3fae8f59d8fc9ce`へ戻し、警告抑制forkを削除
- PackagerのHTML／JavaScriptに`willReadFrequently`を後付けする下流patchと公開APIを削除
- `Silhouette.unlazy()`はmaterialize後にpixel arrayをキャッシュするため、警告回数と実際のread-heavy度を分離
- project source manifest入力で`.yml`／`.yaml`／`.json`を受理し、推奨例を`project.source.yml`へ統一
- manifestを任意化し、root直下で唯一の`.k4.yml`を自動選択。0件／複数件は明示指定なしでfail closed
- canonical source上限を計測に基づき256 KiBから1 MiBへ変更
- 旧`app/`と`release-sources/`を全廃し、公開SB3はGitHub Releasesを配布正本に変更
- 「もう一度」アイコンの円環と矢じりを単一輪郭にし、矢じりの内外形状を均等化

## 互換性と制約

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- package、Standard Runtime reporter、artifact metadataは`4.0.0-rc.6`に揃います。
- `poseRecognition.preview.overlay`を省略した台本は従来どおりポーズオーバーレイを表示しません。
- `overlay`を記述し`visible`を省略した場合は表示し、問題時は`overlay`設定の削除で非表示へ戻せます。
- camera canvasのcontext初期化に失敗した場合はfail closedとし、推論開始前にエラーを返します。
- CPU推論時のCanvas2D readback警告は、性能根拠のない抑制を行わず許容します。
- scratch-renderのSilhouette警告も許容します。Chromiumは共有canvasの2回目のreadbackで警告する一方、
  480×360の同一処理はChrome 149で改善なし、Chrome 151で指定時に約22.4%低速でした。
- Structured Data Standalone／DebugとAction Contextは既定OFFのままです。
- rc.5以前のSB3は埋め込み済みの旧Runtimeをそのまま保持します。
- 3.1／3.2作品はversion 3.2.3の配布SB3で継続利用できます。

## 検証

candidate PRとfreeze PRを分離し、公開前に次を実行します。

```bash
pnpm install --frozen-lockfile
pnpm release:dsl4:check
pnpm verify:full
pnpm release:check
```

検証対象には、TMPose 1.11.0 exact pin、ポーズオーバーレイのSchema／正規化／Composition API接続、
camera canvasの上流責務、公式scratch-render exact pin、Packager readback patchの不在、PoseNet integrity、
offline Chromium、site build、npm package smokeを含めます。

## ロールバック

freeze前に問題が見つかった場合はcandidateを修正し、再検証します。freeze後または公開後は
4.0.0-rc.6を同じversionで差し替えません。問題時はnpmの`next` dist-tagを4.0.0-rc.5へ戻し、
GitHub prereleaseとPagesへ注意事項を追加します。修正版は`4.0.0-rc.7`として公開します。

公開済みartifactはGitHub Releasesで変更・削除しません。過去versionの展開sourceは現行branchへ
重複保持せず、必要な調査では対応するGit tagを参照します。
