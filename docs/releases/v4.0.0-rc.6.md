## 概要

v4.0.0-rc.6は、camera canvasのreadback context初期化をTMPose 1.10.1へ移し、
下流のKamishibaiがTensorFlow.jsの`fromPixels()`経路を補修しない責務境界へ戻す公開候補です。
renderer canvasは別の責務としてscratch-renderのSilhouette共有canvasだけを対象にし、
`getImageData()`を行わないTextBubbleは対象外にしました。

安定版としての推奨は3.2.3を維持し、4.0.0-rc.6は4.0正式公開前の検証に使用します。

## rc.5からの主な変更

- TMPoseを1.10.1へ更新し、camera setup直後にreadback用2D contextを一度だけ初期化
- camera canvasの所有者であるTMPoseへ修正を集約し、Kamishibai側の上流内部実装patchを禁止
- Packagerのscratch-render固定commitを`c69318a6c8d43439fc35fa9e403bf6d2781fdaee`へ更新
- scratch-renderのreadback指定を、実際に`getImageData()`を行うSilhouette共有canvas一件へ限定
- TextBubble向け指定を削除し、readback canvas数の契約を一件へ修正

## 互換性と制約

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- package、Standard Runtime reporter、artifact metadataは`4.0.0-rc.6`に揃います。
- camera canvasのcontext初期化に失敗した場合はfail closedとし、推論開始前にエラーを返します。
- scratch-render側の変更はSilhouetteのreadback指定だけで、microbenchmarkでは有意な速度差を確認していません。
- Structured Data Standalone／DebugとAction Contextは既定OFFのままです。
- rc.5以前のSB3は埋め込み済みの旧Runtimeをそのまま保持します。
- 3.1／3.2作品はversion 3.2.3の配布SB3で継続利用できます。
