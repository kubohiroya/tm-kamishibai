## 概要

kamishibaiハット配下に台本を組み込んだSB3を開くと、「台本ファイルを開く」へ進んでしまう問題を修正しました。
起動時に組み込み台本を検出し、タイトルを閉じると既存の物語開始経路で再生します。
Stage上の名前が空の台本がルートです。名前付き台本はincludeBlocksで参照します。
物語を開始し直す際には現在のブロックを読み直し、編集内容を反映します。
不正な台本は診断を表示し、ファイル選択へ自動で切り替えません。

プロジェクト内の素材とremote素材は編集後の宣言から解決します。
file素材の実体にはSB3内の対応するアセットバンドルが必要です。
既存のファイル実体と参照を保持しながら、プロジェクト素材・remote素材の編集を反映します。

`author-block-dsl`はYAMLをシーンと実命令のブロックへ変換します。
`export-block-dsl`はブロックの接続と入力値からYAMLを復元し、共通frontendで検証します。
includeBlocksによるモジュール分割を保持し、素材・操作・アクターなど8種類の定義を専用ブロックで編集できます。
対応Editorで`blockEditorDialogs=1`を指定すると、専用定義ブロックのJSON値をSchemaフォームで編集できます。
YAMLのコメント・引用符・空行は保持しません。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- CLI・開発環境にはNode.js 24.0.0以上が必要です。Node.js 22の対応を終了しました。
- 台本宣言は`kamishibai [4.0] [ラベル]`ハットへ統一しました。
  旧`whenDsl4Source`と`dsl4SourceFromYamlJson`の互換読取は行いません。
  旧ハットを含むSB3は`K4-BLOCK-SOURCE-REMOVED-001`で拒否します。元のYAMLから対応CLIで再生成してください。
- Stage上には名前が空のルート宣言が1個必要です。名前付き宣言が1個だけでもルートとは解釈しません。
  空でないラベルはSB3全体で一意です。Sprite上の既存の空名宣言は従来の読取規則を維持します。
- 旧`property`ブロックの読取互換を維持します。新しい専用ブロックを旧CLIへ直接渡す互換性は保証しません。
- 古い編集用SB3の埋込拡張は自動更新されません。新しい専用ブロックやフォームを使う際は対応CLIで再生成してください。
  フォームAPIがないEditorでは通常の文字列入力を使います。
- portraitの`placement`・`offset`・`cornerRadius`は省略可能です。省略時は従来の既定値を使います。
- `convert-dsl4`は`TMPoseURL`を再び受理します。rc.10〜rc.22で案内した`TMURL`も同じ意味の別名として維持します。
