## 概要

v4.0.0-rc.13は、Standard SB3に埋め込むTurboWarp TM拡張を`@kubohiroya/turbowarp-tm@3.2.0`へ上げ、
rc.12の公開後に入ったDSL 4.0の変更をまとめた公開候補です。rc.12は公開済みのため、同じversionでは
差し替えず、新しいcandidateとして切ります。

## rc.12からの主な変更

- 埋め込みTurboWarp TMを`@kubohiroya/turbowarp-tm@2.0.0`から`3.2.0`へ更新（#800）
- **破壊的変更**: Standard profileで暗転していた8個のfeature flagを既定ONに変更（#796）
- **破壊的変更**: 変数更新のcore actionを追加し、write blockを畳む（#797）
- BGMの停止・fade-out・音量を標準DSLへ追加（#798）
- `Actor.setText`でcontent run（ruby含む）とplain text射影を追加（#799）

## TurboWarp TM 3.2.0について

TurboWarp TMの「Upgrading from 2.x」のとおり、block surface、composition API、offline PoseNet bundle APIは
変わっていません。composition APIの差分は追加だけ（`selectComputeBackend()`、`getComputeBackend()`、
任意の`compute`／`computeMode`）で、PoseNetの重みシャードはバイト一致です。SB3に埋め込む`dist/tm.js`は
64 KBから73 KBになりました。

TM KamishibaiはTensorFlow.js 1.3.1とTeachable Machine Pose 0.8.6のbrowser runtimeを自前で供給し、
TurboWarp TMの`dist/runtime.js`（TensorFlow.js 4.22.0同梱）は使いません。そのため3.xのcompute backend
negotiationはこの経路では働かず、TensorFlow.jsが選んだbackendをそのまま使います。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- 4.0.0-rc.13のStandard SB3内のmanaged TM extension IDは`kubohiroyatm`です。
- CLI executable名`tm-kamishibai`とcommand体系はrc.12から変更していません。
- #796と#797はStandard profileの既定値とwrite blockを変えるため、rc.12向けに書いた台本の挙動が変わる
  場合があります。
- rc.12以降、say／thinkはTurboWarp BubbleのSVG overlayに描画され、`Scratch.looks`の状態には書き込み
  ません（#730）。台詞を`Scratch.looks`から読んでいた外部の検証は、overlayから読むよう変更が必要です。
- 3.1／3.2作品は推奨安定版3.2.3で継続利用できます。

公開済みSB3、release metadata、旧URL、旧packageの履歴は削除しません。
