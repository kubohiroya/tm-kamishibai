## 対象

- 埋め込むTeachable Machine拡張を3.5.1にする（画像モードがモデルに渡す画素の向きの修正）
- プレビュー停止時に、ブラウザのsocketがCLIの終了を待たせないようにする

## 概要

3.5.1は画像モードの入力を直します。`predict`に反転を頼んでいなかったので、モデルには未反転の画素が
渡っていました。Teachable Machineの学習時はプレビューをCSSで反転しているだけで画素は未反転なので、
video要素を渡す側が反転を頼む必要があります——ライブラリ自身の案内も`predict(element, true)`です。

枠は元から合っています。`predict`はvideo要素なら`videoWidth`/`videoHeight`を読んで中央を正方形に
切り出すので、rc.20で入ったポーズ経路と同じ「フレームの中央正方形」です。足りなかったのは反転だけで、
これでポーズモードと画像モードが同じ正方形を同じ向きで見ます。**ポーズ認識の経路は変わりません。**

CLI側では、プレビューを止めたあとの終了を待たせない修正が入っています。`server.close()`は要求を
送り終えていない接続を待ち続けるので（HTTPの`requestTimeout`は既定で300秒）、ブラウザを閉じたのに
`turbowarp-kamishibai preview`が戻ってこないことがありました。gracefulな終了を試みたうえで、
250ミリ秒の猶予を過ぎた接続は打ち切ります。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- Extension IDもbundleのmemberも変わりません。rc.20のStandard SB3で作った作品はそのまま開けます。
- block surfaceとcomposition APIは変わりません。台本に書くことは何も増えません。
- ポーズ認識の入力・プレビュー・overlayはrc.20と同じです。

### 下流への影響

## 検証

```sh
pnpm verify:full
pnpm pack:smoke
pnpm release:check
```

画像モードの反転は、ライブラリの実装（`cropTo`）と公式の案内の読み、および拡張側のunit testまでの
確認です（Teachable Machineの画像モデルを手元に持っていません）。ポーズ経路は、決定的な1フレームを
webgl／wasm／cpuの3つのbackendに通して確率が小数2桁まで一致すること、`numTensors`が増えないことを
実ブラウザで確認しています。
