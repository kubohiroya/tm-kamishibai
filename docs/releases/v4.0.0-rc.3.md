## 概要

v4.0.0-rc.3は、v4.0.0-rc.2のbrowser authoringと配布経路を維持しながら、
TensorFlow.js初期化時の重複登録警告、作品フォルダー選択時の診断、作者用メニューの日本語表記を
改善する公開候補です。

安定版としての推奨は3.2.3を維持し、4.0.0-rc.3は4.0正式公開前の検証に使用します。

## rc.2からの主な変更

- 同じTensorFlow.js runtimeでbackendとbrowser platformを再登録しないようにし、紙芝居開始時の
  `webgl backend was already registered`、`cpu backend was already registered`、
  `Platform browser has already been set`警告を抑制
- フォルダー選択、台本・asset読込、監視開始の失敗理由を具体的に表示し、エラー画面から作者用メニューへ
  戻れる導線を追加
- 作者用メニューの日本語表記を「ファイルを開く」から「台本を開く」へ変更
- candidateは現在のgenerator、frozen／publishedは保存済みsnapshotを検証するrelease lifecycleをCIへ反映

Canvas2Dの`willReadFrequently`警告（[#564](https://github.com/kubohiroya/tmpose-kamishibai/issues/564)）は
scratch-render由来です。警告抑制だけの独自scratch-render forkは本リリースに含めません。

## 作者向けflow

1. 非埋め込みStandard SB3をTurboWarp Editorで開き、緑の旗を押します。
2. 作者用メニューの「台本を開く」から作品フォルダーを選びます。
3. 外部editorでYAMLやlocal assetを編集します。正常な保存は自動検証後に反映されます。
4. 不正な候補ではlast-known-goodの実行を維持し、具体的な診断を表示します。
5. メニューへ戻り、「配布用SB3を作る」を押します。
6. 保存したSB3を新しいTurboWarp Editor sessionで開き、作品フォルダーなしに実行します。

CLIの`preview-dsl4`、`validate-dsl4`、`build-dsl4`は、CI、batch build、高度な配布profile、
File System Access API非対応環境向けに維持します。

## 互換性と制約

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- package、Standard Runtime reporter、artifact metadataは`4.0.0-rc.3`に揃います。
- browser authoringはFile System Access APIとsecure contextを利用できるChromium系browserを対象とします。
- 選択したfilesystem handle、absolute path、preview token、diagnostic、reload preferenceはSB3へ保存しません。
- remote assetを選択した配布profileはnetwork依存を維持します。offline profileではremote descriptorを拒否します。
- 3.1／3.2作品はversion 3.2.3の配布SB3で継続利用できます。
- 4.0 Standardは3.2の`extensionBundles`をunbundleして生成するartifactではありません。

## 公開手順

1. clean mainでfull verificationとnpm publish dry-runを実行します。
2. `pnpm release:dsl4:freeze`でsource identityとartifact SHA-256を固定し、freeze PRをmergeします。
3. frozen merge commitへannotated tag `v4.0.0-rc.3`を作成してpushします。
4. `npm publish --access public --tag next`で`@kubohiroya/tmpose-kamishibai@4.0.0-rc.3`を公開します。
5. 本文書をrelease notesとしてGitHub prerelease `tmpose-kamishibai v4.0.0-rc.3`を公開します。
6. `pnpm deploy`で4.0.0-rc.3を公開候補として追加し、3.2.3を推奨安定版のまま維持します。
7. npm、GitHub、PagesのURLを`pnpm release:dsl4:record-publication -- ...`でmetadataへ記録します。
8. npm version／dist-tag、GitHub tag／release、Pages上のSB3 version／SHA-256を再確認します。

## ロールバック

freeze前に問題が見つかった場合はcandidateを修正し、再検証します。freeze後または公開後は
4.0.0-rc.3を同じversionで差し替えません。問題時はnpmの`next` dist-tagを直前の検証済みprereleaseへ移し、
GitHub prereleaseとPagesへ注意事項を追加します。修正版は`4.0.0-rc.4`として公開します。

公開済み4.0.0-rc.1／rc.2、安定版3.2.3、version付き3.1／3.2 sourceとartifactは変更・削除しません。
