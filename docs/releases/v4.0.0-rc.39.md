## 音声の準備と再生制御

動画と同じ準備・ID操作の構成で、`audio` / `audioControl` と対応する2つのブロックを追加しました。sound素材または直接URLから停止状態で音声を用意し、同じscene内のIDで終了待ち・バックグラウンド・ループ再生、停止、一時停止・再開、シーク、音量・ミュート・速度を操作します。

```yaml
- audio: {id: music, asset: Theme}
- audioControl: {id: music, operation: play, fadeIn: 0.5, volume: 150, fadeOut: 1}
- wait: 2
- audioControl: {id: music, operation: stop, fadeOut: 0.5}
```

再生・再開時に `fadeIn`・`volume`・`fadeOut`、停止時に `fadeOut` を指定できます。秒数は0以上の有限数です。音量は既定100の0以上の有限数で、50は半分、200は2倍です。再生時の省略値は現在の設定音量を保持します。ブロックの空欄は省略・継承、0は明示的な無音またはフェードなしを表します。setVolume操作の音量はVALUE欄に指定し、再生用VOLUME欄は空にします。

旧 `bgm` / `sound` / `stopBgm` / `setBgmVolume` は互換入口として維持し、BGMのsceneを跨ぐ寿命やcrossfadeも保持します。共通の再生controllerを `@kubohiroya/turbowarp-asset-cache@0.3.0` へ統合しました。音声機能は通常のStandard経路で有効で、有効化URLスイッチは不要です。

## 寿命とブラウザ制約

音声IDはscene単位で最大32件です。scene切替、台本終了、dispose、素材解放で停止して資源を回収します。stopはフェードの完了を待って先頭へ戻し、IDを保持します。loopの周回ごとのfadeOutは行いません。

直接URLは認証情報なしのHTTP(S)に限定し、オフライン配布では同梱素材を使用します。直接URLの音声を別originから取得する場合はCORS対応が必要です。音声付きautoplayはブラウザの許可条件に従い、拒否時は `K4-AUDIO-AUTOPLAY` として診断します。
