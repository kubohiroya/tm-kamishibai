## 概要

v4.0.0は、YAMLを唯一の必須programming surfaceとする紙芝居DSL 4.0の最初の安定版です。台本製作者が
Scratch blockを追加せず、外部editorで台本を編集し、同じproduction frontendで検証、preview、build、
runtime実行できます。配布SB3はruntime、台本、local assetを内包し、remote extension codeへ依存しません。

## 主な変更

- 厳格なYAML 4.0 schema、Source Map、式評価、有限resource limit、cross-surface診断
- scene／action実行、keymap、時系列history、pose、speech、asset preload、custom action
- Object Store、Iterator、JSONPath、Structured Data composition
- `validate-dsl4`、`build-dsl4`、`preview-dsl4 --watch`
- browser-owned TurboWarp local preview、transactional source／asset live reload、共通reload overlay
- optional Source Graph `include`、循環／重複宣言拒否、宣言元相対asset解決
- DSL 3.1／3.2から4.0 YAMLへの明示converter
- source-composed Standard Runtime、作者向けvisible DSL block 0、自己完結SB3

## 互換性と移行

- DSL documentは文字列`kamishibai: "4.0"`だけを受理し、3.xへ暗黙fallbackしません。
- 3.1／3.2作品はversion 3.2.3の配布SB3で継続利用できます。4.0への移行は`convert-dsl4`で別fileへ
  変換し、検証とpreview後に採用してください。
- 新規sourceは`.k4.yml`を推奨します。既存の`.kamishibai.yaml`を含む4種類のsuffixは受理します。
- npm CLIはNode.js 22.12.0以上を必要とします。
- package version、DSL version、Standard Runtime reporterはv4.0.0で`4.0.0`に揃います。

## 既知の制約

- local previewはloopback限定です。remote previewは提供しません。
- `include`は`dsl4SourceIncludes`を明示的に有効化し、file数、個別／合計byte数、深さを指定した場合だけ
  使用できます。既定OFFの単一source経路は維持されます。
- development preview、token、candidate、reload preference、debug surfaceはproduction SB3へ保存されません。
- remote assetはHTTPS、SHA-256、media typeを明示したopt-inだけを受理します。
- 4.0 Standardは3.2の`extensionBundles`をunbundleして生成するartifactではありません。

## Release candidateの検証

公開前に次をすべて成功させます。

```bash
pnpm install --frozen-lockfile
pnpm verify:full
pnpm release:check
```

`verify:full`は固定release source、決定的SB3、unit／Chromium E2E、site buildに加え、実際のnpm tarballを
展開して`./dsl4`、`./builder`、CLI versionを検証します。

## 公開手順

1. release PRをmerge commitでmainへ統合し、catalogの`sourceCommit`がmainのancestorであることを確認する。
2. mainで`pnpm verify:full && pnpm release:check`を再実行する。
3. annotated tag `v4.0.0`を作成してpushする。
4. `npm publish --access public`で`@kubohiroya/tmpose-kamishibai@4.0.0`を公開する。
5. 本文書をrelease notesとしてGitHub Release `tmpose-kamishibai v4.0.0`を公開する。
6. `pnpm deploy`で4.0.0を推奨安定版とするdownload siteを公開する。
7. npm version、GitHub tag／release、Pages上のSB3 version／SHA-256を再確認する。

publish、tag、GitHub Release、production deployはrelease準備PRには含めません。

## ロールバック

公開前はrelease PRをrevertし、3.2.3を推奨安定版へ戻します。公開後は4.0.0を同じversionで差し替えません。
必要に応じてnpm packageをdeprecateし、GitHub Releaseへ注意事項を追記して、修正を4.0.1として公開します。
version付き3.1／3.2 sourceとartifactは削除しません。
