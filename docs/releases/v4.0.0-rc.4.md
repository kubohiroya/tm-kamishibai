## 概要

v4.0.0-rc.4は、DSL4ランタイムを構成する機能拡張へ識別しやすいSVGブロックアイコンを追加し、
6つの外部capability packageを対応する新しいminor versionへ固定した上で、`sb3-toolchain@0.8.0`により
一つのcompactなTurboWarp拡張へ集約する公開候補です。

安定版としての推奨は3.2.3を維持し、4.0.0-rc.4は4.0正式公開前の検証に使用します。

## rc.3からの主な変更

- Asset Manager、Async Input、Bubble、Runtime Expression、SVG Text、TMPoseへ、透明背景・白単色の
  機能別`blockIconURI`を追加
- Kamishibai DSL 4.0 Runtime、Structured Data、Structured Data Debug、Action Contextにも
  個別の`blockIconURI`を追加
- 外部capabilityをAsset Manager 0.11.0、Async Input 0.4.0、Bubble 0.5.0、
  Runtime Expression 0.4.0、SVG Text 0.5.0、TMPose 1.8.0へ更新
- `sb3-toolchain@0.8.0`でRuntimeと6拡張を`kubohiroyakamishibai4`へ静的bundleし、各通常ブロックへ
  由来元の`blockIconURI`を継承。既定のcompact出力により重複する復元カプセルは含めない
- 各memberのextension ID、opcode、ブロック文言、DSL document version、runtime semanticsは変更なし。
  配布SB3内のopcodeはbundle名前空間へ変換

## 作者向けflow

1. 非埋め込みStandard SB3をTurboWarp Editorで開き、緑の旗を押します。
2. 作者用メニューの「台本を開く」から作品フォルダーを選びます。
3. 外部editorでYAMLやlocal assetを編集します。正常な保存は自動検証後に反映されます。
4. メニューへ戻り、「配布用SB3を作る」を押します。
5. 保存したSB3を新しいTurboWarp Editor sessionで開き、作品フォルダーなしに実行します。

## 互換性と制約

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- package、Standard Runtime reporter、artifact metadataは`4.0.0-rc.4`に揃います。
- Structured Data Standalone／DebugとAction Contextは既定OFFのままです。
- ブロック名への絵文字prefixは追加せず、既存projectのopcodeと表示文言を維持します。
- rc.3以前のSB3は埋め込み済みの旧Runtimeをそのまま保持し、rc.4のbundle sourceへ差し替えません。
- 3.1／3.2作品はversion 3.2.3の配布SB3で継続利用できます。
- 公開済み3.xのbyte列は`sb3-toolchain@0.6.0` aliasで再現し、rc.4だけを0.8.0のicon継承とcompact bundleで生成します。
- rc.4の配布SB3単体は直接unbundleせず、version管理されたrelease sourceから個別memberへ復元します。

## 公開手順

1. clean mainでfull verificationとnpm publish dry-runを実行します。
2. `pnpm release:dsl4:freeze`でsource identityとartifact SHA-256を固定し、freeze PRをmergeします。
3. frozen merge commitへannotated tag `v4.0.0-rc.4`を作成してpushします。
4. `npm publish --access public --tag next`で`@kubohiroya/tmpose-kamishibai@4.0.0-rc.4`を公開します。
5. 本文書をrelease notesとしてGitHub prereleaseを公開します。
6. `pnpm deploy`で4.0.0-rc.4を公開候補として追加し、3.2.3を推奨安定版のまま維持します。
7. npm、GitHub、PagesのURLをmetadataへ記録し、公開状態を再確認します。

## ロールバック

freeze前に問題が見つかった場合はcandidateを修正し、再検証します。freeze後または公開後は
4.0.0-rc.4を同じversionで差し替えません。問題時はnpmの`next` dist-tagを4.0.0-rc.3へ戻し、
GitHub prereleaseとPagesへ注意事項を追加します。修正版は`4.0.0-rc.5`として公開します。

公開済み4.0.0-rc.1／rc.2／rc.3、安定版3.2.3、version付き3.1／3.2 sourceとartifactは
変更・削除しません。
