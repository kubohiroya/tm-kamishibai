## 対象

- `poseRecognition.preview.controls`を宣言した作品が起動時に落ちていた不具合の修正

## 概要

カメラプレビューの操作UI（反転ボタンとカメラ選択メニュー）は、台本の`poseRecognition.preview.controls`
で構成します。スキーマはこのキーを受理し、設計文書も本番の機能として書いていましたが、**宣言すると
起動時に落ちていました**。

```
TypeError: cameraPreviewControls app-shell options are required when preview controls are configured
```

rendererもcamera側のportも揃っていて、フラグ`dsl4CameraPreviewControls`もStandard productionで
ONでした。欠けていたのはDOM側の口——container、プレビュー矩形、フレームscheduler——で、これを
渡していたのはtestだけでした。

rc.18は入口がそれを渡します。プレビューの箱はステージのcanvasです。DSL 4.0のスキーマにpreview
positionは無く、story camera lifecycleが起動のたびに`full-stage`を設定するので、ステージの矩形が
プレビューの矩形になります。毎フレーム読み直すため、packagerのようにステージが拡縮されても
controlは追随します。ラベルはlocale対応です。

拒否の位置も直しました。このshellが描けない台本は、ほかの満たせないcapabilityと同じく
environment構築時に拒否します（`K4-HOST-PREVIEW-CONTROLS-001`）。asset prepareの途中で
投げることはもうありません。optionsを読むのは台本がcontrolsを求めたときだけなので、フラグOFFの
hostは従来どおりこのoptionに触れません。

誰も踏んでいなかったのは、`preview.controls`を宣言した作品がまだ無かったからです。この経路を
覆うtestも無く、app側のtestはbundleを組んで読み込むところまでしか見ません。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- Extension IDもbundleのmemberも変わりません。rc.17のStandard SB3で作った作品はそのまま開けます。
- block surfaceとcomposition APIは変わりません。
- `preview.controls`を**宣言していない**作品の挙動は変わりません。宣言していた作品は、落ちる代わりに
  操作UIが出ます。
- 3.1／3.2作品は推奨安定版3.2.3で継続利用できます。

### 下流への影響

Standard SB3のバイト列が変わるため、公開済みartifactをベースとして固定している下流は再pinが必要です。
turbowarp-kamishibai-samplesは`stories/urashima/dsl4-build.config.json`の`runtime`で固定しています。

download catalog、Pagesの推奨表示だけを直前の検証済み組へ戻し、公開済みSB3、release metadata、
旧URL、旧packageの履歴は削除しません。
