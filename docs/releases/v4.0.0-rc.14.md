## 概要

v4.0.0-rc.14は、YAMLとTurboWarpブロックのあいだを往復できるようにするcandidateです。rc.13で公開した
runtimeとDSLの意味は変えず、CLIに2つのsubcommandを足します。`author-block-dsl`はYAML台本をbase SB3の
宣言ブロックとして書き込み、`validate-dsl4 --format canonical-json`は台本の正規形を出力します。
この2つで「手書きYAML → ブロック → YAML」と「ブロック → 動くSB3」の両方がCLIだけで閉じ、下流の
turbowarp-kamishibai-samplesはブロック台本SB3をCI上で生成・検証できます。

埋め込み拡張のversionはrc.13と同じで、DSL document versionも文字列`kamishibai: "4.0"`のままです。

## rc.13からの主な変更

- `validate-dsl4 --format canonical-json`を追加（#835）。production frontendが作るstory documentを、
  mapping keyを全階層でsortし、`sourceRange`と`sourceMap`を値の形で判別して落とした正規形として出力します。
  array順は意味なので保持します。`json` envelopeは従来どおりdiagnosticsだけを返します。
- `author-block-dsl --input STORY.k4.yml --base BASE.sb3 --output OUT.sb3`を追加（#836）。
  `build-dsl4`がすでに読む宣言ブロック（`whenDsl4Source` + `dsl4SourceFromYamlJson`）としてYAML台本を
  base SB3へ書き込みます。`export-block-dsl`の逆方向です。
  - opcodeの形はbase自身の`extensions`から判定します（released baseはbundle経由、development baseは
    runtime直読み）。
  - source pathはStageの名前に`.k4.yml`を付けたものです。readerがそう導出するため、呼び出し側に選択肢は
    ありません。
  - 書き出す前にproduction readerで読み戻し、round-tripできない宣言はファイルになりません。
  - 出力は決定的です（固定block id、sortしたzip entry、共有の固定timestamp）。
  - `include:`を含む台本は現時点では理由を示して拒否します。multi-target形式は後続課題です。
- TypeScript 7でcompileとtype checkを行うよう移行（#833）。
- development dependenciesを更新（#826）。

## ブロック宣言の位置づけ

`author-block-dsl`が書くブロックはauthoring表現です。runtime側のhandlerは不活性で
（`whenDsl4Source`は`false`、`dsl4SourceFromYamlJson`は`undefined`を返します）、作者がTurboWarp上で
台本を読み・直し・改変するために存在します。これを再生できる形にするのは`build-dsl4`です。
したがってこのsubcommandはasset処理を行わず、出力SB3は配布物ではありません。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- 埋め込み拡張とsupport dependenciesのpinはrc.13と同じです（TurboWarp TM `3.2.0`を含む）。
- 4.0.0-rc.14のStandard SB3内のmanaged TM extension IDは`kubohiroyatm`です。
- CLI実行ファイル名は`turbowarp-kamishibai`で、`tm-kamishibai`は非推奨aliasのままです。
- 追加した2つのsubcommandは新規で、既存subcommandの出力と終了コードは変えていません。
- rc.12以降、say／thinkはTurboWarp BubbleのSVG overlayに描画され、`Scratch.looks`には書き込みません。
- 3.1／3.2作品は推奨安定版3.2.3で継続利用できます。
