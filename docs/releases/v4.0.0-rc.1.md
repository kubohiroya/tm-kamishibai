## 概要

v4.0.0-rc.1は、YAMLを唯一の必須programming surfaceとする紙芝居DSL 4.0の最初の公開候補です。台本製作者が
Scratch blockを追加せず、外部editorで台本を編集し、同じproduction frontendで検証、preview、build、
runtime実行できます。配布SB3はruntime、台本、local assetを内包し、remote extension codeへ依存しません。
安定版としての推奨は3.2.3を維持し、4.0.0-rc.1は4.0正式公開前の互換性と公開経路の検証に使用します。

## 主な変更

- 厳格なYAML 4.0 schema、Source Map、式評価、有限resource limit、cross-surface診断
- scene／action実行、keymap、時系列history、pose、speech、asset preload、custom action
- Object Store、Iterator、JSONPath、Structured Data composition
- `validate-dsl4`、`build-dsl4`、`preview-dsl4 --watch`
- browser-owned TurboWarp local preview、transactional source／asset live reload、共通reload overlay
- 非埋め込み Standard SB3の既定development runner、台本file／project directory監視
- YAML更新時のlocal／remote／SB3内project asset再解決と、Editor追加costume／soundの保持
- 非埋め込みdevelopment runnerの`debugger` action停止、breakpoint／step実行UI
- optional Source Graph `include`、循環／重複宣言拒否、宣言元相対asset解決
- DSL 3.1／3.2から4.0 YAMLへの明示converter
- source-composed Standard Runtime、作者向けvisible DSL block 0、自己完結SB3

## 互換性と移行

- DSL documentは文字列`kamishibai: "4.0"`だけを受理し、3.xへ暗黙fallbackしません。
- 3.1／3.2作品はversion 3.2.3の配布SB3で継続利用できます。4.0への移行は`convert-dsl4`で別fileへ
  変換し、検証とpreview後に採用してください。
- 新規sourceは`.k4.yml`を推奨します。既存の`.kamishibai.yaml`を含む4種類のsuffixは受理します。
- npm CLIはNode.js 22.12.0以上を必要とします。
- package version、Standard Runtime reporter、artifact metadataは`4.0.0-rc.1`に揃います。
  DSL document versionは引き続き`4.0`です。

## 既知の制約

- local previewはloopback限定です。remote previewは提供しません。
- `include`は`dsl4SourceIncludes`を明示的に有効化し、file数、個別／合計byte数、深さを指定した場合だけ
  使用できます。既定OFFの単一source経路は維持されます。
- 非埋め込みSB3はdevelopment previewを初期化しますが、token、handle、candidate、reload preference、
  dialog state、debug mode、停止位置はSB3へ保存されません。埋め込み作品SB3はproductionのままで、
  `debugger` actionはno-opです。
- 非埋め込みSB3の監視はYAML generation起点です。project assetまたはlocal fileだけの変更を
  独立candidateにする場合は`preview-dsl4 --watch`のasset live reloadを使います。
- remote assetはHTTPS、SHA-256、media typeを明示したopt-inだけを受理します。
- 4.0 Standardは3.2の`extensionBundles`をunbundleして生成するartifactではありません。

## Release candidateの更新と検証

candidate期間だけ、次のcommandでruntime sourceからversion付きrelease source、決定的SB3のSHA-256、
machine-readable metadataを一括更新できます。同じ入力で再実行しても差分は生成しません。

```bash
pnpm release:dsl4:update
pnpm release:dsl4:check
```

CIと通常の検証は`check`だけを実行し、repositoryを書き換えません。`check`が不一致を報告した場合はhashを
手編集せず、candidateの間だけ`update`を実行します。

公開前に次をすべて成功させます。

```bash
pnpm install --frozen-lockfile
pnpm verify:full
pnpm release:check
```

`verify:full`は固定release source、決定的SB3、unit／Chromium E2E、site buildに加え、実際のnpm tarballを
展開して`./dsl4`、`./builder`、CLI versionを検証します。

## 公開手順

1. candidate PRをSquash & Mergeし、clean mainで`pnpm verify:full && pnpm release:check`を再実行する。
2. `pnpm release:dsl4:freeze`でsource identityとartifact SHA-256を固定し、その変更をmainへ統合する。
3. frozen commitへannotated tag `v4.0.0-rc.1`を作成してpushする。
4. `npm publish --access public --tag next`で`@kubohiroya/tmpose-kamishibai@4.0.0-rc.1`を公開する。
5. 本文書をrelease notesとしてGitHub prerelease `tmpose-kamishibai v4.0.0-rc.1`を公開する。
6. `pnpm deploy`で4.0.0-rc.1を公開候補として追加し、3.2.3を推奨安定版のまま維持する。
7. npm、GitHub、PagesのURLを`pnpm release:dsl4:record-publication -- ...`でmetadataへ記録する。
8. npm version／dist-tag、GitHub tag／release、Pages上のSB3 version／SHA-256を再確認する。

publish、tag、GitHub Release、production deployはrelease準備PRには含めません。

## ロールバック

公開前はcandidate PRをrevertし、3.2.3を推奨安定版のまま維持します。`frozen`または`published`へ遷移した
4.0.0-rc.1は同じversionで差し替えません。必要に応じてnpm packageをdeprecateし、GitHub Releaseへ
注意事項を追記して、修正を4.0.0-rc.2として公開します。正式安定版は別versionの4.0.0として作成します。
version付き3.1／3.2 sourceとartifactは削除しません。
