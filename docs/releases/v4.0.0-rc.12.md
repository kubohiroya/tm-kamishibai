## 対象

- TypeScript移行の基盤整備（[docs/design/typescript-migration.md](../design/typescript-migration.md)）

## 概要

v4.0.0-rc.12は、実行時の振る舞いを変えずに開発基盤をTypeScriptへ移行し始めた公開候補です。
TurboWarp拡張機能side（`@kubohiroya/vite-plugin-turbowarp-extension`系repository）と同じ
toolchain——TypeScript strict、Vitest、`typescript-eslint`、Vite——をこのrepositoryへ持ち込み、
`src/`をcompileした`dist/`をpublishする形へ切り替えました。DSL 4.0の文法、runtime、
CLI command、診断codeは変更していません。

## rc.11からの主な変更

- npm packageの公開面を`src/**/*.js`から`dist/**`へ変更し、`.d.ts`を同梱
- test runnerを`node --test`からVitestへ移行（152 test file、1183 test）
- `typescript-eslint`を導入し、`.ts`にもlint規則を適用
- site buildの出力先を`dist/`から`site-dist/`へ移動し、`dist/`をpackage buildへ明け渡し
- `src/`のmoduleすべて（177 module）をTypeScriptへ移行。残るJavaScriptは生成物2件のみ
- crossfade transitionのeasingを、未検証の文字列のまま適用せず、適用前に検証するよう修正
- `typescript`を`^6.0.3`へ固定（`typescript-eslint`がTypeScript 7に未対応のため）
- DSL 4.0 runtime extensionとlocal preview bundleの生成をesbuildからViteへ移行し、
  `esbuild`をdependenciesから削除（`vite`がdependenciesへ移動）

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- 4.0.0-rc.12のStandard SB3内のmanaged TM extension IDは`kubohiroyatm`です。
- CLI executable名`tm-kamishibai`とcommand体系はrc.11から変更していません。
- **package importer向けの破壊的変更**: `exports`が`./dist/**`を指すようになりました。
  `./builder`、`./converter`、`./dsl4`のsubpath名は同じで、`.d.ts`が追加で提供されます。
  `@kubohiroya/tm-kamishibai/src/...`のような内部pathへ直接importしていた場合は、
  公開subpathへ移してください。
- repository内で作業する場合、`bin/`と`scripts/`はcompile済みの`dist/`を読みます。
  各npm scriptの先頭で`pnpm build:lib`が実行されるため、通常の手順に変更はありません。
- 3.1／3.2作品は推奨安定版3.2.3で継続利用できます。

## 検証

```sh
pnpm verify:full
pnpm pack:smoke
pnpm release:check
```

`pnpm verify:full`はrelease source identity、SB3決定性、extension list、opcode、embedded mapping、
manifest、integrity、Editor／Player／Web／Packager／CLI buildの主要経路、site build、npm package smokeを
検証します。`pnpm release:check`はnpm publish dry-runであり、実際の公開は行いません。

## ロールバック

rc.12を同じversionで差し替えません。問題時は公開済みrc.10または安定版3.2.3を利用し、修正は次の
candidateとして公開します。npm dist-tag、download catalog、Pagesの推奨表示だけを直前の検証済み組へ戻し、
公開済みSB3、release metadata、旧URL、旧packageの履歴は削除しません。
