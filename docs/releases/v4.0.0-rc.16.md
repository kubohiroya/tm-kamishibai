## 対象

- Standard bundleに`@kubohiroya/turbowarp-camera-source@0.15.0`をmemberとして同梱
- 埋め込みTeachable Machine拡張を`@kubohiroya/turbowarp-teachable-machine@3.4.0`へ
- `embedded-extensions.json`と同梱notice中の、実際のpinと食い違っていたversion文字列を訂正

## 概要

カメラを開くのはCamera Sourceだけになります。Teachable Machine拡張3.4.0は自分で`getUserMedia`を
呼ばず、Camera Sourceからleaseを取り、その映像を読みます。Camera Sourceが同じbundleに居れば、
作品側の記述を変えずにこの経路へ切り替わります（`composition.ts`の`startCamera()`が拡張本体の
`startCamera()`をそのまま呼ぶため）。居なければ3.4.0は従来どおり自分でカメラを開くので、
同梱しないという選択はできますが、そのときカメラは拡張ごとに別々に開かれます。

Camera Source 0.15.0は、このbundleのために`getInfo()`へ`docsURI`と`blockIconURI`を足した版です。
bundleのpaletteはmemberごとにアイコンとドキュメントボタンを描くので、これが無いmemberは
paletteの中で一つだけアイコンもガイドへの導線も持たないことになります。

## version文字列の訂正

`scripts/sb3/dsl4-downloadable-release.ts`のmember表と`src/dsl4/runtime-provenance.ts`は、
pinを上げたときに置き去りにされた文字列を持っていました。生成物では
`embedded-extensions.json`の`source.version`と、同梱notice中のversionとして出ていました。

| 対象                          | 記載   | 実際のpin |
| ----------------------------- | ------ | --------- |
| Bubble（member表）            | 0.11.0 | 0.13.0    |
| Teachable Machine（member表） | 3.2.0  | 3.4.0     |
| Teachable Machine（notice）   | 3.2.0  | 3.4.0     |

`integrity`は実バイトから計算していたので、同梱物そのものは正しいものでした。誤っていたのは、
それが何であるかの申告です。Bubbleのnoticeだけがtestで固定されていたため、他が外れていました。

## 互換性

- DSL document versionは引き続き文字列`kamishibai: "4.0"`です。
- 既存のExtension IDは変わりません。bundleに`kubohiroyacamerasource`が増えるので、paletteに
  Camera Sourceのブロック群とドキュメントボタンが現れます。
- block surfaceとcomposition APIは変わりません。Camera Sourceからは何もimportしていません。
  同梱しているのは、runtime上で`Scratch.vm.runtime`越しに出会わせるためです。
- rc.15のStandard SB3で作った作品はそのまま開けます。
- 3.1／3.2作品は推奨安定版3.2.3で継続利用できます。

### 大きさ

bundle拡張のソースは4,337,176 bytes（rc.15比 約+166,000 bytes、base64のmember 1本分）、
SB3は6,901,249 bytes（rc.15の6,849,521 bytesから+51,728 bytes）です。testの上限は
4,300,000→4,500,000 bytes、project.jsonは12,500,000→12,800,000 bytesへ上げました。
いずれもPoseNetの重みがソースへ混入していないことを見る天井で、混入すれば桁で超えます。

### 下流への影響

Standard SB3のバイト列が変わるため、公開済みartifactをベースとして固定している下流は再pinが必要です。
turbowarp-kamishibai-samplesは`stories/urashima/dsl4-build.config.json`の`runtime`で固定しています。
